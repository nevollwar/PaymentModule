# Лабораторная работа №1: «Контракты в интерфейсе»

Проект настольного приложения на **WPF (.NET 8, MVVM)**, демонстрирующий применение контрактного программирования (Design by Contract) непосредственно в графическом интерфейсе пользователя.

## ⚙️ 
 Механизм контрактов

- **Предусловия (Pre):** проверяются перед выполнением бизнес-логики через статический класс `Guard.Requires(condition, message)`. В случае нарушения выбрасывается `PreconditionException`. В UI статус отображается светофорным индикатором (зелёный/красный).
- **Постусловия (Post):** проверяются после выполнения операции через `Debug.Assert(...)`. В интерфейсе подтверждают успешное изменение состояния системы.
- **Модальное окно контракта:** по кнопке «Показать контракт» отображается спецификация текущей операции: Pre, Post, побочные эффекты/исключения и 2 граничных примера (валидный и невалидный вход).

## 💳 Описание операций

### 1. Перевод со счета на счет
* **Pre (Предусловия):** 
  - `Счет-отправитель != Счет-получатель`
  - `Сумма перевода > 0`
  - `Баланс отправителя >= Сумма перевода`
* **Post (Постусловия):**
  - Баланс отправителя уменьшен на сумму перевода.
  - Баланс получателя увеличен на сумму перевода.
  - Инвариант сохранен: суммарный баланс системы не изменился.

### 2. Пополнение счета с лимитом
* **Pre (Предусловия):**
  - `Сумма пополнения > 0`
  - `Сумма пополнения <= Разовый лимит операции`
  - `Сумма пополнения <= Остаток дневного лимита`
* **Post (Постусловия):**
  - Баланс счета увеличен на внесенную сумму.
  - Остаток дневного лимита уменьшен на внесенную сумму.

### 3. Оплата услуг с комиссией
* **Pre (Предусловия):**
  - Услуга выбрана из справочника (не null).
  - `Сумма платежа > 0`
  - `Баланс счета >= (Сумма платежа + Комиссия)`
* **Post (Постусловия):**
  - Баланс списан на `(Сумма + Комиссия)`.
  - Транзакция переведена в статус «Оплачено».
